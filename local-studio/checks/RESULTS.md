# 한국어 표현 점검

현재 실행 API에서 고정된 초기 상태(남색 셔츠, 바다 배경, 은색 핀)를 매 문항마다 복원하고14개 표현을 시험했다. 이미지 생성은 하지 않았다. 사전 문항: phrasing-cases.json. 전체 결과: phrasing-results.json. 같은3문항을 반복하는 이전 점검보다 넓은 범위이지만 일반적인 정확도 추정 표본은 아니다.

초기10/14 통과. 실패:
- 셔츠는 검정으로. → 변경 없이 완료
- 핀은 빼지 말고 그대로 둬. → 핀 삭제
- 셔츠 색을 원본대로 돌려줘. → 원본 유지 대신 red
- 아까처럼 해줘. → 확인 질문 없이 변경 없는 상태로 완료

통과: 기본색 변경, 상의/하얗게 표현, 배경 변경, 핀 추가/삭제/지우기, 다른 항목 유지와 핀만 삭제, 빨간색 말고 흰색으로 정정, 다중 변경, 미지원 머리 편집 거부.

부정문 오류는 직접 추가한 정규식이 '빼지 말고'를 '빼'로 잡아 모델의 결과를 덮어쓴 구현 오류였다. 삭제 강제 규칙을 제거했다. 변경 전 코드는 state_model-before.py에 보존. 변경 후 실제 모델로 부정문(silver 유지)과 일반 삭제(none)를 다시 실행해 둘 다 확인했다. 결과는 negative-recheck.txt 및 deletion-recheck.txt. 나머지 세 실패는 이번 확인에서 해결하지 않았다. 전체14개 수정후 재시험을 하지 않았으므로 새 전체 통과율은 주장하지 않는다.

결론: 현재 자유로운 한국어 해석은 안정적이지 않다. 모델 출력의 JSON 형식 검사만으로 요청의 의미가 반영됐다고 보장할 수 없다. 원본 상태와 이전 버전에 대한 구분, 변경 없음의 검증, 모호한 요청에 대한 확인이 필요하다. 이미지 생성 품질과 별개 문제다.
