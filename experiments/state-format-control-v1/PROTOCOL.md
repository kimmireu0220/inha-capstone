# 전체 대화의 구조화된 상태 추출 대조

2026-10-03. `state-tracking-v2`의 U1 일부 이미지와 자동 상태 추출 오류를 확인한 뒤 설계한 후속 대조다. 이력 U1–U4는 이미 사용한 개발자 작성 대화이며 새로운 일반화 평가가 아니다. 추가 방법의 프롬프트와 출력을 보기 전에 아래 조건을 고정한다.

## 질문

기존의 자연어 프롬프트 종합, 새 요청마다 상태를 갱신하는 방법, 전체 대화에서 최종 상태를 한 번에 추출하는 방법을 비교한다. 마지막 방법에도 동일한 여섯 항목과 동일한 최종 프롬프트 문장 변환을 사용한다. 이를 통해 기존 두 방법의 차이를 해석할 때 구조화된 출력의 영향을 검토한다. 호출 수와 추출 지시가 달라 특정 구성 요소 하나의 인과 효과로 단정하지 않는다.

## 추가 방법

같은 Qwen3 4B 4bit에 전체 8턴 대화와 지원 값 목록을 주고 최종 여섯 항목의 JSON 상태를 추출한다. 두 번째 호출은 원래 대화와 첫 출력을 함께 읽고 최신 요청·삭제·재추가와 대조한다. 두 호출 모두 온도 0, 최대 700토큰이며 예시 정답이나 해당 대화의 정답 상태를 주지 않는다. 여섯 항목의 존재, 중복 키, 지원 값을 코드로 검증한다. 두 번째 출력이 형식상 유효하면 사용하고, 아니면 첫 번째 유효 출력을 사용한다. 둘 다 유효하지 않으면 전 항목 `original`을 사용하고 실패를 기록한다. 결과를 보고 추출 지시를 수정하거나 추가 호출하지 않는다.

## 조건과 재사용

R01–R06, U1–U4, 시드 42·314의 48개 조건 전부를 평가한다. 원본·모델·4스텝·크기와 최종 프롬프트 변환 코드는 기존 96장 비교와 같다. 모든 추가 프롬프트를 먼저 고정하고 상태 점수를 계산한다.

이미 생성한 조건과 원본·최종 프롬프트 바이트·모델·스텝·크기·시드가 모두 일치하면 해당 이미지를 해시 검증 후 재사용한다. 일치하지 않는 조건은 새로 생성한다. 재사용 수와 새 생성 수를 공개하며, 재사용된 이미지를 독립 반복으로 세지 않는다. 기존 두 방법과의 대응 관계를 보존한다.

## 평가와 해석

기존과 같은 여섯 목표, 원본 대비 ArcFace, 모델 호출 수·시간·프롬프트 길이를 보고한다. 재사용된 이미지에는 기존 점수를 연결하고, 새 이미지는 방법명과 기존 점수를 가린 상태에서 Codex와 같은 고정 버전의 Qwen2.5-VL로 평가한다. 알려진 기존 비교와 연결되는 재사용 조건이 있어 완전한 새로운 가림 실험으로 주장하지 않는다. 평가자는 모두 AI이며 독립 인간 평가는 별도 과제로 남는다.

모든 결과를 포함한다. 전체 대화 상태 추출이 더 정확하거나 저렴하면 그 결과를 결론에 반영한다. 새 대화 상태 갱신이 더 유리하면 이 범위에서의 장점과 비용을 함께 보고한다. 기존 96장 결과의 프로토콜·프롬프트·점수는 이 대조에 맞춰 변경하지 않는다.
