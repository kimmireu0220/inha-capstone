# 항목별 처리의 사후 개발 결과

새 모델 호출 없이 N·M의 저장된 일반 추출·재검토 출력을 그대로 사용했다. 이 결과는 해당 오류를 보고 설계한 코드의 개발 성능이며 고정된 별도 검증 결과가 아니다.

| 방법 | N 전체 상태 정확 | N 항목 정확 | M 전체 상태 정확 | M 항목 정확 |
| --- | --- | --- | --- | --- |
| 기존 일괄 검증+복원 제약 | 22/24 | 142/144 | 20/24 | 137/144 |
| 최신 패치 일괄 검증+복원 제약 | 18/24 | 133/144 | 20/24 | 137/144 |
| 항목별 검증+복원 제약 | 23/24 | 143/144 | 22/24 | 142/144 |
| 항목별 검증·복원 제약 없음 | 21/24 | 141/144 | 19/24 | 139/144 |

주 비교의 최종 대화 정확은 N에서 두 방법 모두6/6, M에서 모두5/6이다. 새 미변경 항목 훼손은 모든 대조에서0이었다. 잘못된 재킷·소품 출력이 다른 정상 변경까지 취소시키는 경우에 항목별 처리가 유리했지만, keep으로 잘못 추출한 변경이나 복원 이후 재지정을 일반적으로 해결하지는 못했다.

최신 응답 선택 방식만 바꾸는 것은 N에서 더 나빴다. 따라서 효과를 선택 순서와 혼동하지 않도록 동일한 최신 응답에 일괄 거부를 적용한 대조를 유지한다. [O 고정 검증](../slot-isolation-validation-v1/PROTOCOL.md)의 결과와 이미지 단계 확인 전 해결 방법으로 확정하지 않는다.
