# 웹 편집기 순차 생성 / 일괄 재생성 비교

2026-09-14, 생성 전 계획.

현재 웹 편집기의 `/api/chat`, `/api/generation-settings`, `/api/generate`, `/api/restore` 경로를 사용한다. UI와 같은 서버·프롬프트 생성기·모델 실행 경로에서 두 모드를 비교한다. 브라우저에서는 모드 선택·시드 저장·버전 비교를 별도로 검수한다.

- 원본: 기존 합성 인물 P04. 서버에서 512×768로 정규화.
- 모델: Runpod/FLUX.2-klein-4B-mflux-4bit, MFLUX, 4 steps, low-RAM.
- 시드: 42, 314. 각 시드를 해당 경로의 모든 생성에 사용.
- 요청 순서: `셔츠를 남색으로 바꿔줘.` → `배경을 옅은 파란색으로 바꿔줘.` → `은색 핀 하나 추가해줘.`
- 기대 최종 상태: shirt_color=navy, background=pale blue, pin=silver.
- 순차 생성: 각 요청을 적용한 뒤 한 번 생성. 다음 입력은 현재 버전의 출력. 총 3회.
- 일괄 재생성: 원본 상태로 돌아간 뒤 세 요청을 모두 적용하고 원본에서 한 번 생성. 총 1회.
- 실행 순서: 시드 42는 순차→일괄, 시드 314는 일괄→순차.
- 총 8개 새 출력, 최종 비교 4개. 최종 상태와 프롬프트는 방법 간 동일.

주 지표: 고정 얼굴 ROI [176,44,336,224]의 LPIPS(AlexNet v0.1). 보조 지표: 같은 ROI의 RGB MAE, SSIM. 기존 로컬 비교와 같은 좌표·분석 함수를 사용한다. 결과를 본 후 영역이나 시드를 바꾸지 않는다. 원본 대조에서 MAE=0, SSIM=1, LPIPS≈0을 확인한다.

입력 이미지 스냅샷·프롬프트·출력·시드·실행 시간·해시와 API 작업 기록을 보존한다. 순차 2/3단계 입력 해시가 직전 출력 해시와 같은지, 일괄 입력 해시가 원본과 같은지 검사한다. 실패한 생성은 로그를 보존하고 분석을 중단한다. 성공한 이미지는 선택적으로 재생성하지 않는다. 시간은 요청부터 저장 완료까지이며 순차는 3회 합계로 비교한다.

표본 단위: 한 인물·두 시드. 기존 CLI 실험과 별도 결과로 보고한다.
