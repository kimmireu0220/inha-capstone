# 고정한 요청 검사 방법의 추가 대화 검증

2026-10-06. coverage-repair-v1의 4개 개발 대화 결과를 확인한 뒤, 추출 프롬프트·누락 검사·무변경 값 생략 규칙을 고정한다. 이곳 V1–V4는 그 뒤 작성한 별도 대화다. 같은 개발자가 만든 제한 어휘 대화이며 독립 외부 자료 또는 광범위한 일반화 검증으로 주장하지 않는다. 대화 작성 후 모든 출력을 고정하기 전까지 채점하지 않는다.

## 질문

개발 파일럿에서 누락 검사와 일반 재검토+무변경 값 생략이 모두 16/16이었다. 추가 검증에서 복잡한 검사만의 이점이 있는가? 간단한 무변경 값 생략이 실제 변경을 놓치거나 이전 오류를 유지하는 부작용이 있는가?

## 고정 방법

coverage-repair-v1/run.py의 모델·리비전·추출·일반 재검토·누락 검사 프롬프트와 호출 예산을 그대로 사용한다. 첫 출력 1회와 두 재검토 각 1회로 실제 48회 호출한다. 각 재검토 방법의 예산은 첫 호출을 포함해 32회다. 추가 모델 호출 없이 저장한 첫 출력과 일반 재검토 출력에 기존 ablation.py의 무변경 값 생략 규칙을 적용한다. 규칙은 모델에 입력하거나 정답을 참조하지 않는다.

무변경 값 생략: JSON 중복키를 먼저 거부한다. 모델 출력값이 방법 자신이 유지한 이전 상태와 정확히 같으면 그 항목을 갱신 대상에서 뺀다. 남은 실제 변경에는 기존 어휘 근거 검사를 그대로 적용한다. 이전 상태가 틀린 경우 그 값을 정답으로 보정하지 않는다.

최초 출력과 모든 실패를 저장한다. 실행 전 원래 추론 코드·대조 코드·래퍼·대화·프로토콜 해시를 고정한다. 평가 이후 방법을 수정하면 별도 개발 실험으로 구분한다.

## 평가

16턴의 전체 상태 정확도, 96항목 정확도, 최종 4개 대화 정확도, 대화별 결과와 오류 원인을 모두 제시한다. 추가 수정 방법의 이점은 일반 재검토 및 일반 재검토+무변경 값 생략을 모두 기준으로 판단한다. 작은 자료의 한두 건 차이를 확정 효과로 주장하지 않는다. 이번 검증은 이미지 생성 전의 요청 해석에 한정하며 얼굴 보존·이미지 품질 개선을 주장하지 않는다. 사람 평가 작업은 없다.
